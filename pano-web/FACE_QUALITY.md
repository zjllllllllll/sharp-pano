# 六面质量检查

当前策略为 `face-quality-v2-obvious-failure`。用户在首版诊断后明确调整为：仅明显失效弃用，当前两轮中应拒收第二轮上、下深度，其他局部偏差仅提示。策略不含轮次、相机编号或面名特判；24 张历史返回统一计算。

## 拒收线与提示线

质量分不是生成正确概率。每项在拒收线计 80 分、良好值计 100 分，线性裁剪到 0–100；阶段分数取适用项的最低分。任一阶段拒收，整面新增信息不进入后续链路。

| 指标 | 当前拒收线 | 仅提示线 |
|---|---:|---:|
| RGB SSIM | < 0.70 | < 0.90 |
| RGB 颜色绝对误差 | > 0.12 | > 0.06 |
| RGB 边缘 F1 | < 0.50 | < 0.80 |
| RGB 异常面积 | > 30% | > 10% |
| RGB 最大异常块 | > 15% | > 3% |
| 深度有效比例 | < 90% | < 98% |
| 深度相对误差中位数 | > 15% | > 3% |
| 深度相对误差 P90 | > 50% | > 10% |
| 深度异常面积 | > 40% | > 5% |
| 深度最大异常块 | > 30% | > 2% |

深度异常像素仍以相对误差超过 10% 或模型无效定义；表中面积阈值决定是否整面弃用。源深度有显著层次、返回深度范围不足源的 20% 时，仍硬拒收塌缩。原本平坦的表面不触发塌缩特判。

参照区为实际 Mask 和原始几何未知区外 8 px、原 alpha ≥0.90、边框内 8 px。深度参照还需原始深度有效。卷积窗口完整落在参照区；覆盖至少 20%，4×4 网格至少 4 格达到 25% 有效面积，跨至少两行两列。首版要求 8 格、三行三列，当前放宽空间分布要求。修补 alpha 0.70、开运算、边缘平滑及预览滑块均未改变。

RGB 使用未拼回原图的 GPT 返回；深度使用未校准的原始相机 Z 米值。SSIM 为 512/256 两尺度，色差为 sRGB 均值，边缘允许 2 px 偏差；局部异常八连通，小于 16 px 的 RGB 噪声剔除。算法和完整参数见 `face_quality.py`。

## 数据流

RGB 原始返回 → RGB 检查 → 融合并合成 RGB 全景 → 从统一全景重新截取六面 RGB → LingBot → 原始深度检查 → 联合接受结果包 → SHARP → 原有点剔除和补丁诊断。

- LingBot 使用第七步最终 RGB 全景重新投影得到的六面 RGB（512×512、FOV 100°），与本面深度和内参对齐。
- 拒收面权重为零；有效面重新归一化。有效深度只按重叠权重融合，不按跨面深度差拒绝像素。全景不按 Mask 拼回原深度。
- 接受包绑定场景、相机、Mask、原始 RGB 版本及策略，保存支持域、来源位图、有效修补区和剩余缺口。SHARP 只消费这一包。
- 外推是计算用值，不能进入补丁、法向窗口、KNN 参考集合或下一轮可信空间。原有 82° / K64 / 15 cm、六像素过渡带保留；SHARP 单面与最终补丁质量验收已删除，只记录诊断；过渡带裁剪到有效域。少于 65 个参考点停止，不降低 K。
- 原始推理与评分缓存分开。阈值变化可复用同输入的原始输出；从融合全景重投影的 RGB 输入改变时产生新 LingBot 推理缓存。
- 历史结果不迁移、不改写。旧结果必须重新评估并明确生成接受包后，才能作为新补丁输入。

## 自动尝试

每个逻辑轮次最多三台相机，包含第一台。全部没有有效新增贡献时排除当前失败相机并选择剩余最大 Mask 相机；部分面通过时继续，不逐面重发。

`job.json.quality_run` 持久化次数、目标阶段、尝试 ID、历史结果及状态。浏览器负责实际六面采集；关闭后暂停在 `awaiting_capture`，重开恢复。恢复请求幂等。自动执行不超过用户启动的阶段，不自动开始下一轮。

网络、鉴权、GPU、磁盘及 POST 结果不确定属于执行错误，不转换成质量失败、不消耗更多候选重试。原有不确定 POST 标记继续阻止自动付费重发。相机在补丁成功合并发布后加入已选集合；SHARP 单面及最终补丁诊断不阻断发布。

## 离线报告

```powershell
# 在仓库根目录执行，将 <job-id> 替换为本机已有任务
.\run_python.cmd pano-web/evaluate_face_quality.py pano-web/runs/<job-id> --rounds 1,2 --mode audit
```

输出到独立 `diagnostics/face-quality/<时间与编号>/`：HTML、JSON、CSV、参照区与差异热图。前后校验所有已发布文件和原始模型输入；只新增诊断文件，不发布阶段结果。历史 LingBot 使用旧的混合全景引导，报告明确标记这一点。

只读接口：`GET /api/jobs/<id>/face-quality`；报告文件用显式白名单提供。运行恢复使用现有本机令牌保护的 `POST /api/jobs/<id>/quality/resume`，携带 `attempt_id`。

## 验证

纯 CPU 评分、候选尝试与服务测试在项目内 `.envs/runtime` 环境运行。`test_quality_depth.py` 使用假的 LingBot、假的渲染和 CPU Tensor；`test_novel_gaussian.py` 验证投影、支持域和点剔除，不执行真实模型。

涉及修补模块的测试需从仓库根目录使用 `run_cuda_python.cmd` 启动，以便加载 gsplat CUDA 扩展。具体命令见 [贡献说明](../CONTRIBUTING.md)。

历史验证使用模拟测试和 24 张离线诊断；对应场景数据和报告不随源码发布。
