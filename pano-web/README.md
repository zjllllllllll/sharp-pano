## 五步的严格定义

1. RGB：保存上传图的 RGB 像素，EXIF 方向归正，不做增强。
2. 全景深度：现有 DepthMaster 官方六面联合推理，518 面分辨率、95°。`depth.npy` 是原始米制径向深度；预览 P1–P99 拉伸不改变数值。少量无效像素仅在独立 `conditioning.npy` 最近邻补齐并报告数量；低于 95% 有效覆盖率拒绝继续。
3. 反投影点云：直接读取 `depth.npy`，沿六个已知 100° 相机的 768² 网格射线采样全景径向距离，以 `XYZ = 单位世界射线 × 径向距离` 生成中心，不调用 SHARP 深度预测或学习对齐。保留原有六面/双层/像素索引，两层均来自同一观测表面；初始尺度、旋转、颜色与透明度沿用原有规则。LAS 全量；网页默认全量，也可切换固定随机种子的 1/16 抽样（避免规则抽样产生条纹误导判断）。
4. 初始化高斯：直接取第 3 步缓存的 `GaussianBaseValues`，恢复米制坐标，加入 initializer 的原始尺度、单位四元数、颜色和透明度。不调用 zero-delta composer（其逆深度 epsilon 与颜色截断会改变基值）。
5. 调整高斯：以统一全景深度直接初始化双层，跳过 SHARP 学习深度对齐。保留网络最终预测的位置、尺度、旋转、颜色和透明度，不再强制回投到全景深度。加密子点使用点云子点加单个父高斯的位置偏移，其他字段仍继承该父高斯。没有额外训练或迭代优化。

3–5 步均保留双层，OpenCV 世界坐标：X 右、Y 下、Z 前，米制。PLY 对中心和协方差均做相机转换，沿用已有六面角度权重与光学厚度透明度融合。网页绕 X 旋转 180°显示；下载的数据不变。第 3 步保存直接深度反投影中心及初始化属性，第 4 步导出同一份缓存，不增加网络推理。第 5 步用全景深度初始化后保留 SHARP 最终参数预测，不做预测后的深度回投。

## 验证与调试

- 2D 滚轮放大、拖动；深度可切换彩色/灰度。
- 3D 左键拖动环视、右键平移、滚轮移动，点击画面后 WASD/QE 移动，Shift 加速。
- 三维步骤切换不重置相机；固定方向、视场角、保存/恢复视角，便于一致视角对比初始化与最终结果。
- 初始化与最终高斯均在浏览器加载完整 PLY，不做抽稀或 LOD。Spark 内部压缩是预览编码，下载 PLY 保持原始 float32。
- 调试面板有阶段参数、耗时、点数、模型日志；第 3 步显示反投影点到原相机的距离与输入深度的数值误差，第 5 步显示中心位移、主轴尺度比、透明度变化（采样统计，包含 composer 激活差异）。可下载 JSON。
- 错误可见，支持重试未完成步骤，刷新页面恢复当前任务。GPU 阶段串行运行，避免两个模型同时占用显存。

### 第三步：固定法向筛选 + 距离筛选，以及下游 Mask

- 第一次查看点云时，自动从已有 `base/0..5.npz` 初始化坐标补算法向，不重新运行 DepthMaster 或 SHARP。新任务同样在进入第三步时计算。
- 六面、双层分别恢复为 768×768 XYZ 网格；5×5 像素邻域内做三维协方差平面拟合，逐行分块计算。排除非有限值和相对中心径向距离跳变超过 10% 的邻居；至少 6 个有效邻居，最小/中间特征值比不超过 0.25，中间/最大特征值比大于 1e-6。退化、非平面或支撑不足的法向标记为不可靠，进入下一层距离筛选，而不是永久免于筛选。
- 夹角是 `acos(abs(dot(unit_normal, unit_ray)))`，范围 0–90°，射线来自**原始拍摄中心**，与网页相机移动无关。
- 法向阈值已固定为 **82°（不是百分比）**，隐藏夹角严格大于 82° 的点；移除角度滑块，旧的浏览器角度设置不再生效。常量在 `point_normals.FIXED_NORMAL_ANGLE` 与前端 `point-filter.mjs` 中定义，距离缓存会检查一致性。
- `point_distances.py` 先应用法向 mask，再对保留的**全量三维点**建立 cKDTree。精确查询欧氏 K 近邻、排除查询点自身索引，平均距离单位为米；同位置的其他点仍视为邻居。固定 K 档位 4/8/16/32/64，一次查询最多 64 个近邻，分块计算全部档位；只做一轮，不因滑块删除结果反复重建邻域。若不足 K 个则使用实际可用邻居，完全孤立的单点使用 FLOAT32_MAX 表示无邻居。
- 参数固定为 **K=64、15 cm**，移除 K / 距离滑块、启用开关与参数重置；旧 localStorage 设置不再生效。严格大于阈值才删除，恰好等于 82° / 15 cm 保留（后端和 GPU 均按 float32 比较）。
- 点云同样提供“Mask 前 / 后”按钮：前者恢复完整原始点云，后者同时启用两轮筛选；仅更新 GPU uniform，无需重载或计算，视角保持不变。抽样模式也采用相同规则。
- 法向不可靠的点照常参加 KNN，也会被距离阈值筛掉。统计分别显示法向隐藏数、距离额外隐藏数、最终显示数以及距离清除的法向不可靠点数。
- `cloud-angles-full.bin` / `cloud-angles-preview.bin` 是逐点 float32 角度（-1 表示法向不可靠）；`point-normals.json` 记录参数、源文件签名、统计和耗时；`point-normals.log` 保存进度。生成时逐面核对 XYZ 顺序，保证角度与两种预览一一对应。源文件变化时缓存失效；失败可在页面重试，不阻止查看原始点云。
- `cloud-distances-full.bin` / `cloud-distances-preview.bin` 存放每点 5 列 float32 平均距离（K 档位顺序同上，法向已剔除点为 -1），`point-distances.json` 保存法向阈值、计算参数、距离分位数、源文件签名和耗时。抽样预览直接抽取同一份全量距离，**不会在 1/16 抽样上重新查询近邻**。法向或原始文件变化后距离缓存失效。
- `point_mask.py` 将两轮筛选合并，输出 `point-mask.npz`（六个面的原始双层扁平 bool 数组）及 `point-mask.json`（固定参数、数量、源文件签名、SHA256）。逐面核对原始 XYZ，依据 **面 → 层 → 行 → 列** 传递，不按调整后的坐标做近邻匹配；原来不在第三步点云有效角域中的点也不进入 Mask 版，避免调整后重新出现在边缘。
- 第四 / 五步仍正常运行原生 SHARP；Mask 在导出时按原始身份实际删除高斯，不改变其他高斯的中心、尺度、旋转、颜色或透明度，不改变网络内部的双层结构。两步必须引用同一份 Mask SHA256。`to_vertices(return_indices=True)` 返回原生边缘/透明度剔除后的原始索引，保证不会按剔除后的 PLY 行号错配。
- 每步保存两份完整 PLY：`initialized.ply` / `adjusted.ply` 为原始未筛选版本，`initialized-masked.ply` / `adjusted-masked.ply` 为实际剔除后的版本。默认展示 Mask 后，可在本步切换前 / 后且保留相机；下载按钮对应当前版本。若 Mask 清空结果，仍可下载合法空 PLY 或切回原始版本。
- 已完成的旧步骤显示“生成本步 Mask 对比”。第四步直接利用原缓存补导出；第五步需要重跑同一前向以恢复原始索引。补算必须逐项确认基线与原 PLY 完全一致，否则报错并保留原文件，绝不覆盖不一致的原始基线。
- 原始 `base/`、点云二进制和 LAS 不修改，下载 LAS 仍是完整原始点云。Mask 结果位于独立 PLY；每步 JSON 记录两个版本的点数、哈希、固定参数和所用 Mask 哈希。
- 可用 `http://127.0.0.1:8765/?step=3` 直接打开已有任务的点云步骤。

### 第三步：距离自适应加密

- “加密前 / 加密后”在第三、四、五步均可使用。第三步在 CPU 上生成并缓存新增点，不重跑模型。两种视图均使用 Mask 后原点，视角和点大小不变；切回“Mask 前”会关闭加密。普通全量和 1/16 抽样都支持，抽样新增点来自同一份全量结果，不重新计算邻域或改变预算。
- `point_densify.py` 逐面、逐层遍历原始初始化网格的 2×2 单元，只考虑四个角点都通过固定 Mask 的单元。2 米以内不加密，按 `clamp((r/2)^2,1,4)` 限制局部期望倍率，r 来自原始拍摄中心。再根据横/纵相邻点的三维间距与 7.5 mm 目标间距限制采样；已足够密的方向不加点。局部最多沿两个方向各细分一次，即最多三个新增位置，不识别地面、不调整法向或拟合大平面。
- 连续性保护：所有角点有限、所有单元边长不超过 10 cm，四角径向距离跨度不超过 10 cm 且不超过最近角点距离的 5%。这些是保守的断层检测规则，不保证消除一切小于阈值的遮挡错误；不会跨面、跨层或跨已删除的角点插值。
- 总新增预算不超过 Mask 后原点数的 25%，实际数量还受有效区域和期望倍率限制，不强行填满预算。固定随机种子做加权无放回候选分配，距离更远、间距更大的区域获得更高权重；不会每次切换随机重采样，也不会复制同一父点当作加密。
- 新增位置为原网格水平中点、垂直中点或单元中心。由子像素射线与插值后的逆 camera-Z 反投影，颜色在 linear RGB 中插值后转换到预览 sRGB。是已有深度的插值，不是新增测量或细节恢复。
- 只写 `cloud-dense-added.bin`、`cloud-dense-added-preview.bin`、`cloud-dense-sources.bin` 和 `point-densify.json/log`。新增点作为单独的 Points 对象叠加，原点云的筛选属性和数组不变。每个新增点保存面 / 层 / 像素 / 子位置身份，可核查四角 Mask。调试面板记录参数、点数、距离分布、缓存哈希和耗时。
- 原始 `base/`、点云文件、LAS 保持不变；第三步加密前后下载按钮均明确为**原始 LAS**。新增点的面 / 层 / 像素 / 子位置身份传递至第四、五步。
- 检查：`python -m unittest -v test_point_densify test_point_normals test_point_distances test_point_mask test_platform`，`node --test test_point_filter.mjs`。覆盖远近权重、密集轴不加密、遮挡/Mask 边界、相机变换、逆深度插值、预算、索引、缓存复用、抽样子集、源数据不变和 API 串行/失败恢复。

## 结构与环境

### 高斯加密与快速切换

- `gaussian_densify.py` v3 仅追加子高斯，已有高斯所有参数保持不变。父点为第三步子位置编码 `id // 3` 指定的原像素（单元锚点），同面、同层，不按空间最近邻匹配。初始化中心与加密点云一致；调整中心为 `新增初始中心 + 父最终中心 - 父初始中心`。
- 子高斯的所有非 XYZ 字段直接复制父高斯导出值，包括尺度、四元数、SH 颜色和已经完成六面边缘融合的透明度，保证逐字段相等。不再插值这些参数、不再插值网络 delta、不设置网络 hook、不做面积分摊或缩放，也不对新高斯重复做边缘透明度融合。父高斯被原生剔除或四角不通过 Mask 时不创建对应子高斯。不做法向旋转、平面拟合或语义识别。新增叠加可能增强局部遮挡，但不会因缩小旧高斯而引入空隙。
- 第四、五步导出 `*-dense.ply`，加密前同次推理基线为 `*-compare-baseline.ply` / `*-compare-masked.ply`。旧 `initialized/adjusted[-masked].ply` 不覆盖。旧任务用 `/api/jobs/<id>/gaussian-densify/<4|5>` 补生成；新任务正常步骤自动生成。对比两边使用同一次前向的精确源索引，避免跨运行的浮点阈值差异导致行号错位。
- 浏览器共享 `common / removed / children` 三个部件，分别组合为 Mask 前、Mask 后和加密后；加密切换只开关 children，原高斯对象始终不变。已经完成的图片、深度彩色/灰度、点云全量/抽样及两步高斯均预加载。界面提示“预加载完成”后切换只改变可见性，不再请求模型文件或重新解析，保留相机。首次生成/预加载和 GPU 排序仍有成本，不保证任意硬件严格零延迟。
- 切换任务释放缓存；重新生成旧步骤时释放过期缓存；手动生成加密时先释放预览内存。GPU 运行与 CPU Mask 工作共享现有锁。调试记录包含加密算法、基线、父点继承规则、跳过计数和文件哈希。旧任务可复用 `dense-work-5-<face>.npz` 的原始 vertices/source，旧版插值 children 不再读取，因而可在 CPU 上重生成 v3。
- 回归：`python -m unittest test_gaussian_densify test_point_densify test_point_normals test_point_distances test_point_mask test_platform`；`node --test test_view_cache.mjs test_point_filter.mjs`。

- `server.py`：标准库 HTTP 服务；在现有 sharp 环境运行，Pillow 验证上传；限定文件访问、随机写操作令牌。
- `worker.py`：DepthMaster 用既有 depthmaster 环境；SHARP 用既有 sharp 环境；进程完成后释放 CUDA。新增纯 Python `laspy==2.6.1`，未改动 torch/CUDA。
- `static/`：无框架前端；Three 0.180.0、Spark 2.2.0 经 npm 固定并在本地提供，不依赖运行时 CDN。[Spark 文档](https://sparkjs.dev/docs/)。`npm ci` 可恢复前端依赖。
- `runs/<任务编号>/`：上传图、每一步结果、内部基值缓存和日志。每次新上传建新任务，不覆盖上一个。当前页面恢复最近任务；左侧步骤是当前图的阶段历史。
- 默认 Python 路径 `%LOCALAPPDATA%/miniforge3/envs/{sharp,depthmaster}/python.exe`。

本平台是现有模型链路的观测入口，不修改 `ml-sharp` 或 DepthMaster 模型源代码。后续要增加算法参数，应保存参数快照、使受影响的下游结果失效并重新运行，不能只改预览冒充新推理结果。

回归检查：sharp 环境运行 `python -m unittest -v test_platform`；完成五步后，`python verify_run.py runs/<任务编号>` 可只读校验 PLY/LAS、哈希、中心一致性和最终参数变化。

点云 / Mask 回归：`python -m unittest -v test_point_normals test_point_distances test_point_mask test_platform`，以及 `node --test test_point_filter.mjs`。覆盖已知平面夹角、坐标变换不变性、深度断层、退化法向、先法向后 KNN、自身排除与重复点、全量/抽样索引、缓存、GPU 阈值边界、移动与原生剔除后的身份映射、PLY 精确子集及原始文件不变。
